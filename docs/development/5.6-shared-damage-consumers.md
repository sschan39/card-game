# 5.6 — Shared damage rule consumers

Status: common pipeline/hooks implemented in Milestone 5; approved generic result/prevention consumers implemented in Milestone 7. Inspected at `60e9349`, 12 October 2026. [Development index](README.md).

## Purpose and structure

Damage semantics belong to a shared engine path used by combat and effects.

| Module | Owns |
|---|---|
| `src/engine/damage-service.ts` | Pure `DamageRuleRegistry.modify` and complete-board `consequences` hooks |
| `src/engine/damage-keywords.ts` | `planDamageResults`: lifelink, deathtouch, infect/wither and loyalty/defense results |
| `src/engine/replacement-rules.ts` | Prevention/protection, scaling, redirection and destruction prohibition |
| `src/engine/proposed-events.ts` | Replacement selection and nested damage-result planning |
| `src/engine/state-based-planner.ts` | Resulting lethal/zero-toughness/counter/player settlement |

Effective/retained source characteristics determine result keywords/controller. Fully prevented damage produces no damage event, lifelink gain or deathtouch mark. Damage remains distinct from ordinary life loss. A recipient with multiple applicable permanent types receives each applicable result. Destruction prohibition/regeneration belongs to removal semantics, not to subtracting damage.

## Flow

```text
Assignment hooks → damage replacement/prevention → actual assignments
 → generic result instructions → result replacements → atomic application
 → actual damage events/consequence hooks → simultaneous SBAs
```

## Extension boundary and remaining work

New result consumers or prevention operations must preserve exact identities, actual dealt amounts and shared batching. Deferred combat assignment consumers, such as a Deathtouch lethal-assignment adapter, are separate from marking dealt deathtouch damage. No automatic allocation is authorized. Protection blocking likewise remains a deferred combat consumer.

## Acceptance evidence

`tests/engine/damage-pipeline.test.ts` covers shared hooks/complete-board consequences. `tests/engine/removal-damage-rules.test.ts` covers actual prevention/results, protection, counters and destruction/regeneration. `tests/engine/m7-boundaries.test.ts` covers result replacements moving a recipient and invalid recipient types.

## Stop condition

Stop if a keyword is embedded in a card handler/combat loop, prevention changes only displayed damage, or life-loss instructions are incorrectly reported as dealt damage.
