# 5.1 — Simultaneous damage and source attribution

Status: implemented shared atomic damage batches; result replacements/consumers were extended in Milestone 7. Inspected at `60e9349`, 12 October 2026. [Development index](README.md).

## Purpose and structure

Accumulate damage from all assignments without overwriting earlier sources or exposing a partially damaged board to SBAs.

| Module | Owns |
|---|---|
| `src/types/damage.types.ts` | `DamageAssignment`: source snapshot, exact recipient, amount and combat/preventable metadata |
| `src/engine/damage-service.ts` | `planDamage`, `validDamageAssignments` and pure registry hooks |
| `src/engine/proposed-events.ts` | Assignment/result replacements and nested atomic continuations |
| `src/engine/game-reducer.ts` | `reduceDamageBatch` and `APPLY_DAMAGE_BATCH` through the operation-outcome boundary |
| `src/engine/applied-events.ts` | Final dealt amounts/source events, distinct from result life/counter changes |

Combat and spell damage use the same planner. Each positive safe-integer assignment keeps its source. Player losses accumulate through separate result instructions, so sources with power 2 and 3 produce total loss 5. Permanent references include revision. Only players and effective Creature/Planeswalker/Battle permanents receive supported damage. Zero/negative amounts cannot heal or create damage events.

## Flow

```text
All assignments → pure modifiers → valid recipients → proposed damage replacements
 → result instructions/replacements → one APPLY_DAMAGE_BATCH
 → final source-attributed events → consequences/checkpoint
```

## Extension boundary and remaining work

Hooks return proposals/consequences, never commit or grant priority. A valid semantic damage batch may commit even when replaced results leave state equal. Result replacement must not erase the dealt-damage event. Full support for exotic damage rules requires typed operations/scenarios, not a new combat-only damage path.

## Acceptance evidence

`tests/engine/damage-pipeline.test.ts` covers accumulated sources, complete-board observation and invalid amounts/recipients. `tests/engine/replacement-transactions.test.ts`, `tests/engine/m7-boundaries.test.ts` and `tests/engine/operation-outcomes.test.ts` cover actual replaced results, nested pauses and equal-state semantics. Combat/socket coverage uses the same path.

## Stop condition

Stop if damage becomes repeated absolute life assignments, source metadata is lost, or an intermediate recipient gets an SBA/checkpoint before the batch completes.
