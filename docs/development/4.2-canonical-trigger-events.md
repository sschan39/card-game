# 4.2 — Canonical committed events

Status: supported cast/draw/discard/life/departure/combat/step events implemented; generic shuffle added in 8.1. Inspected at `8715503`, 12 October 2026. [Development index](README.md).

## Purpose and structure

Triggers consume what actually occurred, including semantic operations whose final state stays equal.

| Module | Owns |
|---|---|
| `src/types/game-event.types.ts` | Payload contracts and event drafts/batches |
| `src/engine/applied-events.ts` | Legacy before/after derivation and explicit operation-event ownership |
| `src/types/operation-outcome.types.ts` | Rejected/unchanged/committed operation boundary |
| `src/engine/game-engine.ts` | Commit, event identities, event-time contexts and publication |
| `src/engine/trigger-manager.ts` | Canonical event-to-trigger mapping |
| `src/shared/game-logger.ts` | Generic committed timeline recording |

Movement reasons distinguish draw/discard/cast from generic transfers. Battlefield departures emit leave; only a creature reaching graveyard emits death. Life events carry incremental gain/loss, and damage retains its own amount/source rather than inferring damage from life loss. Upkeep/end-step and declaration/completion events belong to actual entry/completion. Successful shuffle owns `LIBRARY_SHUFFLED` even for an unchanged permutation.

## Flow

```text
Proposed instructions → replacements → validated committed outcomes
 → generic mutation metadata + one owner for semantic events
 → batch/event IDs → chronological history/context → publish → discover triggers
```

An operation's omitted `events` uses legacy derivation; a present list owns semantic output, even when empty. Events are not emitted while planning effects. Nested damage results use the same outcome boundary.

## Extension boundary and remaining work

Add payload, actual producer, trigger map and history participation deliberately; not every diagnostic event belongs in rule history. Logging remains generic. Richer rule events must record sufficient identity/source context at commit, rather than reconstructing it from a later room. Durable event replay and hidden outgoing projections retain 9.3/0.3 scope.

## Acceptance evidence

`tests/engine/trigger-events.test.ts` covers reasons, positive increments, sourced damage, step ownership and noncreature departures. `tests/engine/applied-events.test.ts` covers committed batches. `tests/engine/operation-outcomes.test.ts` covers equal-state success, nested events and JSONL. Matching socket scenarios are in `tests/server/live-routing.test.ts`.

## Stop condition

Stop if events are emitted before commit, cumulative totals replace event increments, or artificial state changes are introduced to force semantic success.
