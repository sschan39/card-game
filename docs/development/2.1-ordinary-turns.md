# 2.1 — Ordinary turn structure

Status: implemented ordinary two-player sequence and response windows. Inspected at `c651cda`, 12 October 2026. [Development index](README.md).

## Purpose and scope

Represent a turn as live steps with declarations, entry actions and response windows. Extra/skipped steps and turns belong to 9.1; cleanup decisions and mana lifetime have their own documents below.

## Current structure

| Module | Owns |
|---|---|
| `src/types/game.state.types.ts` | `TURN_SEQUENCE` and `Phase` |
| `src/engine/state-machine.ts` | `PhaseStep`, `planNextStep`, transition entry actions and pass continuations |
| `src/engine/game-engine.ts` | `advancePhase`, committing each step, checkpoints and interruption |
| `src/shared/turn-utils.ts` | `isMainPhase` and `declarationPlayer` |
| `src/client/components/PhaseBar.tsx` | Step labels, declaration controls and priority passing |

The sequence is untap (`stateTurnStart`), upkeep, draw, precombat main, beginning combat, attackers, blockers, combat damage, end combat, postcombat main, end and cleanup. Only untap and ordinary cleanup are automatic. Both main phases permit sorcery timing. Draw proposes an attempt even with an empty library; the setup snapshot controls the first turn's draw.

## Flow

```text
Two consecutive passes with empty stack
 → plan one successor against live room
 → commit entry actions and phase
 → settle checkpoint/choices/triggers
 → declaration, response window, or next automatic step
```

An uncompleted declaration has an owner and no priority. Attackers belong to the active player; blockers belong to the defender. After declaration, active-player priority resumes in that same step. Zero attackers still get a response window, then skip blockers and damage. Combat damage may itself pause for manual allocation.

## Extension boundary and remaining work

Add entry actions through the phase planner and existing proposal pipeline. Never compute all future steps before settling the current one. The damage-pass hook can repeat damage with responses; new keyword consumers remain deferred. Player shortcuts, land play, mana draining, mulligans and full cleanup are separate open items.

## Acceptance evidence

`tests/engine/ordinary-turn.test.ts` drives a complete turn, declaration ownership, zero attackers, both main phases, phase triggers and instant responses. `tests/engine/rules-progression.test.ts` covers recomputation after an intervening trigger. The actual-server zero-attacker transcript is in `tests/server/live-routing.test.ts`. These paths were included in the verified `c651cda` suite; this document adds no new runtime claim.

## Stop condition

Stop if a new phase requires a speculative whole-turn room, bypasses a declaration or grants priority during an unfinished choice.
