# 7.1 — Proposed-event replacement boundary

Status: implemented typed proposal processing before authoritative reduction. Inspected at `60e9349`, 12 October 2026. [Development index](README.md).

## Purpose and structure

Replacement/prevention changes what will occur; triggered notifications describe what actually occurred. Keep those pipelines distinct.

| Module | Owns |
|---|---|
| `src/types/proposed-event.types.ts` | Event variants, exact references, transaction frames and replacement operation schema |
| `src/engine/proposed-events.ts` | `planProposedMutations`, `resumeProposedChoice`, preview/lowering and sequential draw processing |
| `src/engine/replacement-rules.ts` | Applicability/operation handlers and affected-player query |
| `src/engine/game-engine.ts` | Prepare then commit outcomes; identify persisted choices |
| `src/engine/applied-events.ts` | Final actual semantics, never replacement-choice speculation |

Proposals distinguish damage, destruction, sacrifice, discard, zone transfer, individual draw, life, poison and counters. Source/recipient references preserve UUID/revision. A completed proposal lowers to reducer instructions with internal processed markers, avoiding a second replacement pass. These markers are prepared-engine metadata, not a player authorization shortcut.

## Flow

```text
Action/effect/combat/SBA instructions → typed proposals
 → unused applicable replacement → transformed descendants → reevaluate
 → prepared actual instructions → reduceGameOperation → committed events/history
```

Sequential instructions preview prior settled results. Multi-card draws become individual attempts against the current library; empty attempts remain replaceable before failed-draw state. Simultaneous matching uses the declared shared board, carrying provisional finite-registration consumption forward. A paused transaction commits none of its own gameplay prefix/tail.

## Extension boundary and remaining work

Add event schema, conversion/lowering, matching and actual-event/delta scenarios together. Entry-copy/control/face and fuller family consumers remain 8.3. A generic registered operation may extend existing events without adding a separate orchestrator. [Operation outcomes](8.1-committed-operation-outcomes.md) retain semantic successes independent of equality; not every operation needs a replacement event.

## Acceptance evidence

`tests/engine/proposed-events.test.ts` covers pure plans, changed applicability and descendant tracking. `tests/engine/replacement-transactions.test.ts` covers atomic prefixes/tails and actual consequences. `tests/engine/m7-boundaries.test.ts` covers successive draws and ordinary failed-draw loss. Existing actual-server replacement scenarios exercise the real boundary.

## Stop condition

Stop if replacement edits committed state, post-event notifications are used to undo an event, or untrusted input can request a prepared/internal bypass.
