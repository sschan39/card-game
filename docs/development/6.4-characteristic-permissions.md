# 6.4 — Effective permissions and restrictions

Status: shared target/cast/activation consumers implemented; damage/attachment protection added in Milestone 7; protection blocking and general zone access remain open. Inspected at `60e9349`, 12 October 2026. [Development index](README.md).

## Purpose and structure

Use the same effective values in options, announcement and resolution where their respective rules require checks.

| Module | Owns |
|---|---|
| `src/shared/action-permissions.ts` | Cast/activate prohibit and instant timing grants; effective Flash |
| `src/shared/target-legality.ts` | Current structural/permission target queries |
| `src/shared/protection.ts` | Effective source qualities shared by targeting, damage and attachments |
| `src/engine/action-validator.ts` / `modifier-registry.ts` | Existing validation facades |
| `src/engine/option-service.ts` | Advertise effective legal actions |
| `src/engine/effect-resolver.ts` | Resolution-start targeting revalidation |

Prohibitions win over timing grants. Instant/Flash timing still requires priority, allowed zone and payable costs. Casting restrictions do not retroactively counter a cast spell. Targeting uses effective type/control/P/T and effective shroud/hexproof/protection. Permission scopes may apply dynamically to later cards. Source qualities include colors, types/subtypes and colorless/mono/multicolor categories.

## Flow

```text
Characteristic layers → applicable permission rules
 → option/announcement query → lock action
 → resolution targeting query against current/retained source information
```

## Extension boundary and remaining work

Timing permission is not possession or access to another zone: 8.1 must add an explicit access query and source lookup. Protection blocking is a deferred combat consumer; common quality matching alone does not enable it. Multiplayer opponent/team relationships need 9.2's profile. Keep restrictions declarative and use shared queries on existing client/server paths.

## Acceptance evidence

`tests/engine/characteristic-permissions.test.ts` covers effective target permissions, Flash, prohibitions, grants/removal and control. `tests/engine/source-information.test.ts` covers retained-source revalidation. `tests/server/live-routing.test.ts` covers gained Hexproof and effective Flash/granted mana options. Protection damage/attachment cases are in Milestone 7 scenario files.

## Stop condition

Stop if a timing grant skips priority/costs, a blueprint allowed-zone field grants access by itself, or client options use a different permission model from execution.
