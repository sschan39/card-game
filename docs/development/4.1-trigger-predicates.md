# 4.1 — Trigger discovery and predicates

Status: implemented for the supported canonical event map. Inspected at `8715503`, 12 October 2026. [Development index](README.md).

## Purpose and structure

Discover which ability triggered without choosing targets or resolving it.

| Module | Owns |
|---|---|
| `src/engine/trigger-manager.ts` | `discoverTriggers`, scan-set construction, event mapping and collector coordination |
| `src/engine/trigger-matching.ts` | `triggerMatches`: subject, controller, type and subtype filters |
| `src/types/card.types.ts` | Triggered ability, `TriggerFilter`, intervening condition and use-limit data |
| `src/engine/rule-conditions.ts` | Declarative condition context/evaluation |
| `src/engine/card-characteristic-service.ts` | Effective abilities and characteristics of each witness |

Discovery returns `PendingTrigger` records with source, controller, ability/effects and triggering event. Card events normally match the same zone/revision object; watchers opt into another/any. Personal draw/discard/cast and step events default to controller filtering. Legacy entry effects run only for their entering object. Filters use effective characteristics and cannot identify self by physical UUID alone.

## Flow

```text
Committed event + contextual room → relevant scan set → effective matching abilities
 → subject/controller/type predicates → condition/intervening checks → pending records
 → manager collects stack proposals and use reservations
```

## Extension boundary and remaining work

Extend canonical events, the event-to-trigger map and authored predicates together. Discovery stays read-only; no target choice or immediate effect application belongs here. Delayed registrations are independent witnesses through 4.4. More exotic trigger categories/format semantics require explicit schema and scenarios; event strings alone do not implement them.

## Acceptance evidence

`tests/engine/trigger-matching.test.ts` covers self/another, controller/opponent, original revisions and normalized predicates. `tests/engine/trigger-manager.test.ts` covers discovery/coordination. `tests/server/live-routing.test.ts` distinguishes self-entry from another-creature entry. Historical accepted gates are recorded in [the Milestone 4 audit](../project-audit/milestone-4-completion.md).

## Stop condition

Stop if a watcher requires a named-card branch, all abilities react blindly to an event label, or discovery inserts/resolves objects directly.
