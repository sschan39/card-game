# 2.7 — Cleanup and failed draw

Status: damage/effect cleanup and failed-draw loss implemented; hand-limit decisions and repeated cleanup workflow remain open. Inspected at `c651cda`, 12 October 2026. [Development index](README.md).

## Purpose and current structure

| Module | Responsibility |
|---|---|
| `src/engine/state-machine.ts` | Cleanup entry instructions; ordinary draw attempt |
| `src/engine/game-reducer.ts` | Clear damage/deathtouch, expire end-of-turn pools, failed-draw state and delayed-registration expiry |
| `src/engine/proposed-events.ts` | Draw replacements and successive attempts against current results |
| `src/engine/state-based-planner.ts` | Failed-draw loss and simultaneous outcome settlement |
| `src/engine/game-engine.ts` | Checkpoint, pause and ordinary automatic progression |
| `src/types/choice.types.ts` | Existing generic discard choice kind; no dedicated cleanup continuation |

Cleanup currently plans `CLEAR_DAMAGE` followed by `CLEAR_END_OF_TURN_EFFECTS` in one batch. It clears deathtouch marks, expires continuous/replacement entries with end-of-turn lifetime, and cleanup phase entry removes matching delayed registrations. Checkpoints occur after the batch, so losing a toughness buff does not cause an intermediate death while damage is still marked.

## Current flow

```text
Enter cleanup → clear damage and expire effects → checkpoint
 → stop if trigger/choice/terminal state → otherwise next turn's untap/upkeep

Draw attempt → applicable replacements → actual card movement or failedDraw
 → checkpoint → simultaneous win/draw outcome if needed
```

Empty library alone does not lose the game: an unprevented unsuccessful draw does. Replacement can suppress the attempt; successive draws observe earlier results. A terminal outcome stops later progression.

## Missing cleanup structure and proposed extension

No maximum-hand query or hand-limit discard stage exists. Generic discard choices during spell/ability announcement cannot stand in for cleanup. Add a room-owned cleanup continuation that performs required discard, then the simultaneous cleanup actions, then checks whether SBAs/triggers require a response window and another cleanup. Resume that cursor after choices/stack work; do not advance directly to the next turn. Define maximum-hand modifiers through a general query, with any profile default in `src/config.ts`.

## Acceptance evidence and remaining gates

Current damage/effect ordering is covered by `tests/engine/state-machine.test.ts`; draw/replacement behavior by `tests/engine/m7-boundaries.test.ts` and `tests/engine/replacement-transactions.test.ts`. Future scenarios must prove no-discard cleanup, exact excess discard, no maximum/modifiers, stale or invalid answers, discard/death triggers opening priority, another cleanup after those resolve, reconnect within cleanup, both-player mana lifetime and no turn increment until completion.

## Stop condition

Stop if cleanup requires resolving triggers before simultaneous actions finish, bypasses replacement on discard, or uses an announcement continuation to invent a normal player action.
