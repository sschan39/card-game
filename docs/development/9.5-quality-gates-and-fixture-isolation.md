# 9.5 — Coverage, negative actions and fixture isolation

Status: verification/negative-action gates implemented; coverage policy and immutable fixture/catalog boundary remain open. Inspected at `60e9349`, 12 October 2026. [Development index](README.md).

## Current structure

| Module | Current contract |
|---|---|
| `package.json` / `.github/workflows/ci.yml` | Both typechecks, full Vitest suite and production build |
| `vitest.config.mts` | Node test discovery; no configured coverage thresholds/provider |
| `src/server/action-packet.ts` / `src/engine/player-commands.ts` | Packet shape and common action boundary |
| `tests/server/live-routing.test.ts` | Unknown actors, unsafe packets, disabled debug and real lifecycle cases |
| `src/library/card-factory.ts` | Cached blueprint returned/shared by instantiated cards |
| `tests/helpers/test-room-factory.ts` | Local room fixtures and opt-in library filling |

Negative tests already cover many action/resource/identity failures. A green test count does not show branch coverage or all rule families. Cached blueprints are mutable at runtime; tests must clone before changing definitions. Existing copy/reassignment patterns reduce leakage but do not establish an enforced immutable catalog API.

## Proposed flow

```text
Measure active rule-module coverage → inspect uncovered decisions → add meaningful scenarios
 → set justified thresholds → CI gates

Immutable catalog input → instance state + cloned synthetic fixture definition → isolated rooms/tests
```

## Extension boundary and remaining work

Choose coverage tooling only when measuring actual source; do not invent a percentage target from test counts. Thresholds should protect meaningful branches without excluding difficult modules. An immutable catalog interface belongs with 8.5; fixture helpers must avoid mutation of shared cache/blueprints. Preserve zero-resource/empty-library negative cases rather than globally repairing their setup. Centralize any gate/runtime settings appropriately.

## Acceptance required

Coverage includes active engine/client boundaries, CI actually enforces selected thresholds, malformed/illegal packets leave state/events unchanged, cloned fixture changes cannot leak to another instance/test, and representative randomized ordering does not expose shared state. New coverage/fixture policies need concrete failure-before-fix evidence.

## Stop condition

Stop if a threshold passes by excluding active rules, fixtures mutate the shared catalog, or negative actions are accepted merely to keep existing tests green.
