# 2.2 — Player turn shortcuts

Status: ordinary passing and lean debug skip implemented; player shortcut/auto-pass preferences remain open. Inspected at `c651cda`, 12 October 2026. [Development index](README.md).

## Purpose

Let a player request progression while preserving the opponent's response opportunities and requested stops. The existing debug `end_turn` is a development facility, not this workflow.

## Current structure

| Module | Current contract |
|---|---|
| `src/engine/player-commands.ts` | `enter_battle` validates and passes once; `end_turn` requires flow debug mode and an empty stack |
| `src/engine/state-machine.ts` | `passPriority` returns none/resolve/advance; `planNextStep` supports debug `skipToEnd` |
| `src/engine/game-engine.ts` | Debug skip rereads each step and stops for rules work, terminal state or new stack |
| `src/client/components/DebugControls.tsx` | Existing debug skip control |
| `src/config.ts` | Central default debug mode, snapshotted by each room |

The command descriptor is authoritative: either room member may use enabled flow debug controls. The standalone `src/engine/handlers/end-turn-handler.ts` still describes/validates an older active-player-only path; it does not define the current descriptor's rights or progression.

## Current and proposed flow

```text
Current ordinary: enter_battle → one pass → opponent response → second pass → beginning combat
Current debug: end_turn → skip to end → cleanup/next turn → stop on rules work or stack
Proposed shortcut: request stop boundary → pass only while valid → pause on action/choice/stop → normal checkpoint
```

## Proposed structure and extension points

Keep shortcut intent separate from `Phase`. A room-owned serializable preference/request should specify its owner and requested stop, while the engine produces normal passes against each live state. Define whether a pause consumes the request before implementation. Use the existing command boundary and priority coordinator; preferences must never assign the opponent's choices or skip stack responses. Any new defaults belong in `src/config.ts`.

## Remaining work and acceptance

No shortcut state, requested-stop schema or ordinary finish-turn action exists yet. Required scenarios: opponent instant interrupts; phase/step trigger interrupts; pending choice interrupts; declaration still belongs to its owner; configured stop is reached; reconnect preserves intent; rejected commands do not consume another player's window. Existing debug regressions in `tests/engine/player-commands.test.ts` and `tests/server/live-routing.test.ts` must remain valid.

## Stop condition

Stop if ordinary shortcuts reuse the debug skip, silently submit an opponent's pass or need a client-only timer to control engine progression.
