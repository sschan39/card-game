# 6.3 — Static abilities and dynamic scopes

Status: implemented query-time static discovery with declared zones and grouped effects. Inspected at `60e9349`, 12 October 2026. [Development index](README.md).

## Purpose and structure

A static source applies while eligible and sees current matching objects, including later entrants.

| Module | Owns |
|---|---|
| `src/types/continuous-effect.types.ts` | `StaticAbility`, active zones, defining flag, effect groups and scopes |
| `src/engine/characteristic-layers.ts` | Derive static entries from effective intermediate abilities; refresh unstarted definitions |
| `src/engine/continuous-effects.ts` | Represented room cards, source identity and scope matching |
| `src/engine/printed-abilities.ts` | Printed/fallback ability input |

Static definitions are not copied into the stored continuous pool. Queries derive them from current effective abilities. Ordinary statics default to battlefield; explicit `activeZones` enables other represented zones. Defining abilities default to all represented zones. Control-relative scopes use effective source controller. Source/grant timestamps and origin-qualified ability IDs determine order.

## Flow

```text
Effective source ability in eligible zone → derived static parts
 → dynamic current recipients → ordered layer application
 → refreshed effective values when source/recipients change
```

Parts with the same `group` form one effect across layers; default grouping is per ability. Independent effects must use distinct groups. Started groups preserve their continuation/recipients; removal before an effect starts prevents it applying. Newly granted statics can contribute within the current layer.

## Extension boundary and remaining work

Do not turn a static anthem into a resolved frozen recipient list. Adding command/other represented zones requires room-card discovery and active-zone contracts together. Full aura/equipment generation/lifecycle is 8.2. New defining expressions remain typed schema extensions, not callbacks in definitions.

## Acceptance evidence

`tests/engine/continuous-layers.test.ts` covers later entrants, departure, ability removal/grant, grouped continuation and defining counts. `tests/engine/continuous-lifetime.test.ts` covers source-zone timestamps/revisions. Real-server static entrant/source departure scenarios are in `tests/server/live-routing.test.ts`.

## Stop condition

Stop if static copies linger after a source becomes ineligible, dynamic recipients are frozen without a rule reason, or later entrants require per-card registrations.
