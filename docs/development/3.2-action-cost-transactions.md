# 3.2 — Shared announcement and cost transactions

Status: supported mana/life/tap/untap/discard/source-sacrifice costs implemented. Inspected at `c651cda`, 12 October 2026. [Development index](README.md). Related: [mana payment](2.4-mana-payment.md).

## Purpose and current structure

An invalid action pays nothing; a committed action keeps its paid costs even if its stack object is later countered.

| Module | Responsibility |
|---|---|
| `src/engine/action-choices.ts` | Gather missing announcement selections without paying |
| `src/engine/action-costs.ts` | `actionCostError`, `planActionCosts`, `planManaActivation` |
| `src/engine/handlers/play-card-handler.ts` | Casting source reservation, modes/targets/divisions and spell movement |
| `src/engine/handlers/activate-ability-handler.ts` | Same cost planner plus independent ability stack object |
| `src/engine/game-engine.ts` | Complete-choice revalidation and committed proposal/checkpoint boundary |
| `src/engine/proposed-events.ts` | Replacement processing for resulting instructions |

`planActionCosts` previews selected mana activations against earlier results, then plans the final cost. It validates all required discard selections, ownership and exclusions. Tap/untap require a live controlled source and obey creature summoning restrictions; sacrifice currently means the source. Life and discard amounts must be nonnegative safe integers. Contradictory orientation and unknown cost fields reject.

## Flow

```text
Announce selections → pure nested-mana preview → validate final cost
 → prepare all instructions → replacements/commit
 → actual events and checkpoint → priority
```

Preview never publishes events or checks SBAs. A cast card is reserved against nested discard payment. On an invalid final action, the previewed mana/taps/discards never reach authoritative state. Pending choices retain serializable action data and are revalidated before clearing the request. Once committed, countering the resulting object does not refund payment.

## Extension boundary and remaining work

Extend one typed cost schema/planner and the choice preparation together. [Declared generic costs](8.4-announcement-bindings.md) and [base/alternative routes with mandatory extras](8.4-cost-routes.md) now derive one concrete cost before this planner. Selected sacrifice of other permanents, optional extras/cost modifiers and loyalty remain separate open scopes in 8.3/8.4. A general payment-window model is still open in 2.5. Do not equate a handler's pure validation/proposal calls with two payments: only the committed mutation sequence pays.

## Acceptance evidence

`tests/engine/action-costs.test.ts` covers combined costs, foreign/duplicate/source discard rejection, orientation, rollback, no double-tap, nested source reservation and mana discard/sacrifice. `tests/engine/pending-choices.test.ts` covers unpaid prompts and nested mana discard choice. Keep replacement transaction and actual-server payment regressions alongside new cost consumers.

## Stop condition

Stop if a cost is committed before the full action validates, a payment requires an early checkpoint, or a primitive silently ignores unsupported cost fields.
