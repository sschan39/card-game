# Shared numeric values — Slice A implementation plan

> Execute inline, task by task, using the approved [numeric-value design](8.4-numeric-values.md). This checkout and `codex/milestone-0` remain the user's selected workspace. Slice B requires its own checkpoint.

**Goal:** use one evaluator for typed numeric expressions in existing effect, condition and characteristic consumers while preserving their sampling/retention points.

**Architecture:** a pure evaluator dispatches registered numeric queries through transient read capabilities. Consumer adapters supply a rules view or intermediate layer board, materialize concrete numbers, and retain existing gameplay validation. Definition validation and continuous-entry planning reject unsupported/malformed expressions before mutation.

**Tech stack:** TypeScript, Vitest, existing reducer/proposal/choice/transport pipeline; bundled Node executable at `C:/Users/shunm/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node.exe`.

## Constraints

- Engine first; no named cards, catalog additions, new client components, new settings or player choices.
- One syntax/evaluator for constants, bindings, queries, addition and multiplication. Gameplay binding lifecycles remain Slice B.
- Preserve legacy nonnumeric conditions/paths and event values. Numeric failures under boolean nesting are unresolved, not a successful negation.
- Static expressions use the intermediate layer board; resolved continuous values freeze at creation. No characteristic-facade recursion inside layer queries.
- Exact source incarnation/departure information remains authoritative. Existing mutation planning, events, skips and JSON recovery remain owners.
- Stop before ad hoc consumers, arbitrary scripts, implicit binding inheritance or a generic pipeline bypass.
