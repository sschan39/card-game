# 6.2 — Characteristic layers and dependency ordering

Status: implemented supported layer operations through one read-only facade. Inspected at `60e9349`, 12 October 2026. [Development index](README.md).

## Purpose and structure

Derive effective values without editing printed blueprints or trusting cached displayed stats.

| Module | Responsibility |
|---|---|
| `src/types/continuous-effect.types.ts` | Typed operations, scopes and effective result |
| `src/engine/characteristic-layers.ts` | `resolveCharacteristics`, staged board evaluation, grouped static continuations |
| `src/engine/effect-ordering.ts` | `nextEffectIndex`: dependencies and timestamp fallback for cycles |
| `src/engine/card-characteristic-service.ts` | Full/convenience queries, effective blueprint and copiable-only blueprint |
| `src/engine/source-information.ts` | Separate effective/copiable retained values |

Stages are copy, control, text, type/subtype/supertype, color, abilities/keywords, defining P/T, base P/T, deltas/counters, switching, then permissions. The operation selects its stage; legacy `layer` metadata is descriptive. Within a stage, defining effects precede ordinary effects, then dependencies override timestamps. Cyclic components use timestamp order internally; outside dependents still wait. Applicability/operation signatures are reevaluated after each application.

## Flow

```text
Printed values + represented cards → applicable entries/static definitions
 → layer-by-layer dependency/timestamp fold → counters/switches → permissions
 → effective result for engine and current UI
```

Started grouped effects retain later parts/recipients when a later layer removes their generating ability. Unstarted definitions refresh after text/ability changes. Text transformations preserve names/identifiers. Copiable queries stop after layer 1 and exclude counters/damage/later buffs.

## Extension boundary and remaining work

Add a typed operation, stage, transform, dependency signature and consumer scenarios together. The implemented expression schema is numeric/count based; arbitrary card-text interpretation and all exotic interactions are not claimed. A new consumer uses the facade rather than a second layer evaluator or blueprint mutation.

## Acceptance evidence

The historical accepted gate is in [the Milestone 6 audit](../project-audit/milestone-6-completion.md).

## Stop condition

Stop if an effect is implemented by overwriting blueprint/state characteristics, pool position substitutes for timestamp/dependency order, or a consumer bypasses effective queries.
