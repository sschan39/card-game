# 6.5 — Effect identity, timestamps and ability grants

Status: implemented room-monotonic entry identity/order and stable grant identities. Inspected at `60e9349`, 12 October 2026. [Development index](README.md).

## Purpose and structure

Remove exactly one effect, order it independently of pool position, and keep surviving granted abilities selectable when another grant expires.

| Module | Responsibility |
|---|---|
| `src/engine/continuous-effects.ts` | `nextEffectSequence`, `nextEffectTimestamp`, entry normalization |
| `src/types/continuous-effect.types.ts` | Entry ID, timestamp and source incarnation |
| `src/engine/game-reducer.ts` | Commit counters, duplicate-ID handling and exact removal |
| `src/engine/characteristic-layers.ts` | Static IDs/groups and effect-qualified granted ability IDs |
| `src/server/sync-service.ts` | Pool/counter/entry changes in ordinary deltas |

Effect ID and timestamp have different meanings. Equal timestamps do not merge entries. Room sequences/timestamps survive expiry/serialization and consider represented sources. Source UUID plus revision prevents old dependent entries reviving on reentry. Granted ability IDs include entry identity/addition position; expiring an earlier duplicate does not rename the survivor. Legacy source-based removal remains supported for old callers.

## Flow

```text
Prepared entry → assign identity/timestamp/source revision → commit
 → effective grant IDs/options → selected activation
 → remove chosen ID or expiry → delta/snapshot → remaining identities stay stable
```

## Extension boundary and remaining work

New removal uses exact IDs. Old source-based compatibility must not become the default for new consumers. Durable migration of legacy entries is 9.3; current optional fields support existing in-memory fixtures, not a versioned persistence claim. Do not use array indices as enduring identity.

## Acceptance evidence

`tests/engine/continuous-lifetime.test.ts` covers equal timestamps, monotonic identity, exact removal and reentry. `tests/engine/continuous-layers.test.ts` covers duplicate granted statics, stable surviving grants and grant timestamps. Existing sync/reconnect scenarios preserve pool/sequence state.

## Stop condition

Stop if effect expiry renames surviving abilities, ID and ordering collapse into one array index, or removing one source effect indiscriminately deletes independent effects.
