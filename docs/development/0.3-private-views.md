# 0.3 — Private outgoing views

Status: Explicitly deferred by owner for debugging.

Inspected source baseline: `ad6a96e`, 12 October 2026. [Development index](README.md). Source inspection documents current structure; test paths below identify verification responsibilities, not a new passing run.

## Purpose

Eventually project authoritative state into player-specific snapshots, deltas, events and choices without losing the server's full debug state.

## Current structure

- `src/server.ts` — snapshot/join/reconnect send paths.
- `src/server/sync-service.ts` — mutation-to-delta transport.
- `src/types/game.room.types.ts` — authoritative room representation.
- `src/types/choice.types.ts` — choices and continuation data that may contain hidden information.

The current debug-oriented room model is not a private-view guarantee. Protecting hand counts in selected delta branches is insufficient when snapshots, stack metadata, histories, queue entries or choice continuations expose authoritative card data.

## Flow

```text
Authoritative room/event/choice → one viewer projection → snapshot or delta → client store
```

## Extension boundary

A future projection service owns audience policy for every outgoing path. Reveal state from 8.1 supplies explicit exceptions. Keep developer inspection at the authoritative server boundary.

## Remaining work and modification notes

Do not implement until this deferred scope is resumed. Then define the projected schema and sequence/reconnect behavior together, including spectator/debug access.

## Stop condition
