# 0.2 — Terminal convergence

Status: Implemented terminal processing.

Inspected source baseline: `ad6a96e`, 12 October 2026. [Development index](README.md). Source inspection documents current structure; test paths below identify verification responsibilities, not a new passing run.

## Purpose

Make simultaneous losses converge on one stable result and stop all later gameplay.

## Current structure

- `src/engine/state-based-planner.ts` — gathers player losses and places END_GAME after simultaneous changes.
- `src/engine/game-reducer.ts` — terminal room guard and END_GAME state.
- `src/engine/game-engine.ts` — terminal command/checkpoint boundaries.
- `src/client/components/GameScreen.tsx` — result presentation.

The planner computes survivors from the complete loss set. The reducer freezes the terminal snapshot; checkpoint processing discards pending work. Other simultaneous mutations must commit before END_GAME freezes the reducer.

## Flow

```text
Atomic batch → collect all losses → commit simultaneous effects → END_GAME → freeze gameplay → snapshot/delta/reconnect
```

## Extension boundary

Add loss reasons to the typed result and simultaneous planner. UI and sync consume the same outcome; no winner-by-loop-order logic.

## Remaining work and modification notes

Preserve the complete batch when adding new loss conditions. Broader multiplayer outcomes depend on 9.2 rather than extending two-player assumptions silently.

## Acceptance evidence

- tests/engine/game-over.test.ts and tests/engine/state-based-extended.test.ts cover stable and simultaneous outcomes.
- tests/client/game-over.test.ts and tests/server/live-routing.test.ts cover display and live terminal/reconnect behavior.

## Stop condition

Stop if a new loss consumer ends the game before other simultaneous losses are gathered or resumes play by clearing status manually.
