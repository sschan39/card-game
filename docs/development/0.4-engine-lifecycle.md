# 0.4 — Engine lifecycle

Status: Implemented initialization/replacement/disposal structure.

Inspected source baseline: `ad6a96e`, 12 October 2026. [Development index](README.md). Source inspection documents current structure; test paths below identify verification responsibilities, not a new passing run.

## Purpose

Keep exactly one active rules-listener set per room and release listeners/timers when rooms or the server close.

## Current structure

- `src/server.ts` — replaceRoomEngine, room recovery/destruction and server-close cleanup.
- `src/engine/game-engine.ts` — initRoom and dispose.
- `src/engine/action-service.ts` — trigger-manager ownership.
- `src/server/reconnect.ts` — stable socket/player maps and room cleanup.

Replacing the room engine disposes the old engine and initializes the new one against authoritative state. Engine initialization is repeat-safe; disposal ends its listener ownership. Disconnect grace timers belong to the server lifecycle.

## Flow

```text
Room state → dispose previous engine → construct → initRoom → serve actions; destroy/close → dispose and release room resources
```

## Extension boundary

New rule registries may register global handlers at startup, but per-room listeners remain owned by the room engine. Serializable pending rules work survives reconstruction via room data.

## Remaining work and modification notes

Preserve ownership when adding recovery/persistence. A recovered engine must restore managers and pending continuations, not merely hold the room object.

## Acceptance evidence

- tests/engine/engine-lifecycle.test.ts checks listener/disposal behavior.
- tests/server/live-routing.test.ts exercises actual source-server join/replacement/destruction/shutdown seams.

## Stop condition

Stop if recovery needs manually emitting missing triggers, resurrecting a disposed manager or leaving both old and new engine listeners active.
