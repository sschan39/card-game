# 5.3 — Manual combat damage allocation

Status: implemented; automatic allocation remains explicitly deferred. Inspected at `60e9349`, 12 October 2026. [Development index](README.md).

## Purpose and structure

The source controller chooses the split. Every positive-power source with recipients gets a choice, including a single-recipient source.

| Module | Owns |
|---|---|
| `src/types/combat.types.ts` | Plain damage-pass state, requests and accepted allocations |
| `src/engine/combat-service.ts` | `startCombatDamage`, `answerCombatDamage`, recipient keys and live-plan revalidation |
| `src/engine/choices.ts` | Known options, exact totals and integer allocation validation |
| `src/engine/combat-rules.ts` | Additional allocation constraints and lethal thresholds |
| `src/client/components/ChoicePanel.tsx` | Existing distribution controls |

Active-player requests precede defender requests. Full nonnegative power is assigned; omitted options mean zero. Ordinary multi-block splits and overassignment are supported. The existing Trample adapter requires lethal assignment to surviving blockers before player spillover. Recipient keys distinguish player IDs and permanent UUID/revision pairs; extensions are deduplicated.

## Flow

```text
Reconciled board + damage pass → snapshot all requests
 → controller allocations → revalidate live plan and rule constraints
 → persist accepted answer → next source
 → all answers complete → simultaneous shared damage batch → checkpoint/priority
```

No damage commits while any allocation is outstanding. Changed requests reject stale answers without accepting a partial transaction. `combatDamage` plus the pending continuation survives serialization/reconnect.

## Extension boundary and remaining work

Keep manual choices and the existing panel. New rule constraints register through hooks; they do not choose splits on behalf of the player. Richer destinations depend on 5.7. Do not restore obsolete blocker assignment ordering or a lethal-first heuristic.

## Acceptance evidence

`tests/engine/combat-choices.test.ts` covers splits, overassignment, invalid/stale/foreign answers, Trample, serialization and overlapping recipients. `tests/server/live-routing.test.ts` reconnects after a controller allocation and commits one damage batch to both clients.

## Stop condition

Stop if a default split pays damage before confirmation, answer handling applies one source early, or a new client component is required instead of extending the existing protocol.
