## Purpose

Keep server types, client types, runtime support and the production build visible as separate gates.

## Current structure

- `package.json` — engines and named typecheck/test/build scripts.
- `.github/workflows/ci.yml` — Node 24 install, both typechecks, tests and build.
- `src/client/tsconfig.json` — client compiler boundary; tsconfig.json owns server compilation.

CI installs locked dependencies, checks both source graphs, runs Vitest, then compiles the server and bundles the React client. A successful Vite build alone does not establish server or client type safety.

## Flow

```text
Clean checkout → npm ci → typecheck:server → typecheck:client → test → build
```

## Extension boundary

New subsystems use the same gates. Add targeted scenario coverage with the feature; reserve new gate tools for a demonstrated consumer. Runtime/version settings live in package metadata, application settings in src/config.ts.

## Remaining work and modification notes

Keep gate names stable and document exact failure evidence. Inspect CI results separately from local commands; historical test counts are not current runs.

## Acceptance evidence

- README.md documents the commands and active source paths.
- For a code milestone, npm run typecheck:server, npm run typecheck:client, npm test and npm run build must all exit 0.

## Stop condition

Stop if passing a gate would require excluding active source, skipping failed scenarios or claiming historical output as a new run.
