# 4.5 — Simultaneous witnesses and departure information

Status: implemented shared predeparture witnesses for simultaneous SBA batches and retained source snapshots. Inspected at `8715503`, 12 October 2026. [Development index](README.md).

## Purpose and structure

A watcher leaving with other permanents must still see the relevant simultaneous departures. Array iteration order must not determine whether its ability exists.

| Module | Responsibility |
|---|---|
| `src/engine/state-based-planner.ts` | Gather simultaneous settlement from one characteristic snapshot |
| `src/engine/game-engine.ts` | State-based cause, shared source capture and departure event contexts |
| `src/engine/applied-events.ts` | Actual leave/death payloads with departure snapshots |
| `src/engine/trigger-manager.ts` | Departure discovery from preceding battlefield plus final relevant history |
| `src/engine/source-information.ts` | Preserve effective/copiable characteristics and original identity |

For state-based departures, the engine captures each source from the complete preceding battlefield. Departure discovery uses that preceding room, while history predicates observe the simultaneous batch's completed history. Ordinary sequential instructions retain their own before/after contexts and chronological history. Entry discovery uses committed after-state. Queued trigger source information is refreshed for departures later in the same committed batch.

## Flow

```text
Shared live snapshot → simultaneous SBA plan → all actual changes
 → leave/death events with preceding sources and batch history
 → departed/surviving witnesses discover triggers
 → repeat SBA settlement → schedule captured triggers
```

## Extension boundary and remaining work

Simultaneity must be explicit in the proposal/batch cause, not inferred from consecutive mutations. New simultaneous effect families need a declared transaction contract under Milestone 7/8; this guarantee for SBA settlement does not make every multi-instruction spell simultaneous. Retain UUID plus zone/revision when correlating old witnesses with pending objects.

## Acceptance evidence

`tests/engine/applied-events.test.ts`, `tests/engine/source-information.test.ts` and `tests/engine/delayed-history.test.ts` cover dying witnesses, derived departure values and shared death history. `tests/server/live-routing.test.ts` settles simultaneous deaths before offering trigger ordering, with an empty final battlefield.

## Stop condition

Stop if witnesses are reconstructed from the final battlefield, a simultaneous rule is implemented by iteration-order effects, or departure snapshots use reset/reentered card data.
