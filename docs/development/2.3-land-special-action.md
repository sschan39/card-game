# 2.3 — Land special action

Status: ordinary hand land play implemented and verified through [V2](vertical-refinement/02-start-to-spell-resolution.md), 13 October 2026, starting at `f1daa26`. Broader allowance modifiers and cross-zone play remain deferred. [Development index](README.md).

## Purpose and demonstrated gap

Previously all hand cards used the spell pipeline, so lands created spell stack objects and no per-turn allowance existed. The `play_land` action now moves a live hand land directly and records its accepted play. Spell preparation and lower-level cast handlers reject effective Lands before opening announcements.

## Implemented responsibility boundaries

| Unit | Responsibility |
|---|---|
| `ACTION_IDS.playLand` / command boundary | Carry actor, card UUID and current nonnegative integer zoneRevision; validate ordinary game readiness |
| `validateLandPlay(room, playerId, data)` | Effective Land in actor's hand, active player, either main phase, priority, empty stack, current allowance |
| `TurnHistory.landPlays` / `RECORD_LAND_PLAY` | Count accepted plays per player; reset through existing newTurnHistory on actual turn advancement |
| `playLandHandler.propose` | Return direct MOVE_CARD and RECORD_LAND_PLAY in one existing proposal transaction |
| Existing reducer/proposals | Apply actual destination, preserve physical UUID and advance zone revision |
| Existing options/client action routing | Advertise and submit the same supported action |

`SetupConfig.landPlaysPerTurn` snapshots the room allowance, default one and configurable down to zero. `landPlayLimit(setup?)` in `src/config.ts` owns the fallback for legacy rooms/settings. No effect-based allowance hook was added without a consumer. Cast-only timing grants/prohibitions do not control this special action.

## Flow

```text
Hand option → land action → validate access/timing/allowance
 → prepare direct movement → replacements/actual commit
 → record play → checkpoint → active player retains priority
```

Land play does not create a spell object or cast event. Movement and bookkeeping remain uncommitted while a replacement choice is pending; the saved transaction survives JSON serialization and restores priority after completion. Accepted redirected/cancelled entry still consumes one play. A rejected action consumes none; generic land entry does not count as a play. Cross-zone play permissions remain separate work; blueprint allowed-zone data alone must not authorize possession/access.

## Remaining work and acceptance

`tests/engine/play-land.test.ts` covers both main phases, first/second play, own-turn/priority/stack rejection, effective hand types, custom allowance, stale/missing references after leave/return, direct entry/no SPELL_CAST, generic entry, replacement pause/decline/cancel/redirect and an ordinary new-turn reset. Existing zone-transition/entry/checkpoint tests remain the foundations. `tests/server/live-routing.test.ts` now plays the normal configured land, produces mana and resolves a targeted spell through sockets and ordinary passes on both clients.

The V2 browser transcript proves visible rejection/option parity, mana production, local targeting cancellation, normal spell resolution, successful land play on a later turn and allowance/board restoration after reload. Final suite: 1044 tests in 80 files, both typechecks and production build passed; independent review found no remaining important issues. Broader allowance effects, cross-zone access and rules families remain open; this completion covers ordinary hand play only.

## Stop condition

Stop if land play requires suppressing a spell's stack/cast events after the fact, naming a particular land, or bypassing `moveCard` and actual-event generation.
