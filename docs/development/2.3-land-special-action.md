# 2.3 — Land special action

Status: open; hand cards currently use the spell pipeline. Inspected at `c651cda`, 12 October 2026. [Development index](README.md).

## Purpose and demonstrated gap

Land play needs a direct special action with a per-turn allowance. `src/types/action.ids.ts` has no `play_land`; `src/types/game.player.types.ts` has no land-play count. `src/engine/handlers/play-card-handler.ts` builds a spell stack object for a hand card without a land-specific special-action route. `src/engine/option-service.ts` advertises the same cast action for hand cards. A land blueprint is not evidence of land-play rules.

## Proposed responsibility boundaries

| Unit | Responsibility |
|---|---|
| Known action ID and command | Carry actor and exact source reference; validate ordinary game readiness |
| Land-play query | Effective Land type, allowed source zone, active player, main phase, priority, empty stack, current allowance |
| Turn state/history | Count successful plays in the current turn; reset on an actual turn switch |
| Pure planner | Validated direct zone-transfer instruction and successful-play bookkeeping |
| Existing reducer/proposals | Apply actual destination, preserve physical UUID and advance zone revision |
| Existing options/client action routing | Advertise and submit the same supported action |

These are proposed responsibilities, not exported APIs. Decide the allowance representation and how permission/modifier effects change it before implementation. The default limit and any profile setting belong centrally, not in a card handler.

## Flow

```text
Hand option → land action → validate access/timing/allowance
 → prepare direct movement → replacements/actual commit
 → record play → checkpoint → active player retains priority
```

Land play does not create a spell object or cast event. Cross-zone play permissions need the general access boundary from 8.1; blueprint allowed-zone data alone must not authorize possession/access.

## Remaining work and acceptance

Implement the action, allowance hook, turn reset, option parity and actual-server route together. Scenarios must cover both main phases, first/second play, opponent/priority rejection, changed effective types, increased allowance, source reservation and stale references, no stack/counter target, entry triggers, reconnect and a new-turn reset. The existing movement contract is covered by `tests/engine/zone-transitions.test.ts`; no current scenario proves land-play fidelity.

## Stop condition

Stop if land play requires suppressing a spell's stack/cast events after the fact, naming a particular land, or bypassing `moveCard` and actual-event generation.
