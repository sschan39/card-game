# 3.4 — Whole-object stack resolution

Status: implemented legality decision, sequential instructions and final structural destination. Inspected at `c651cda`, 12 October 2026. [Development index](README.md).

## Purpose and current structure

Determine whether the complete spell/ability resolves before moving its source or executing its untargeted instructions.

| Module | Responsibility |
|---|---|
| `src/engine/action-service.ts` | Select top object and request a pure plan |
| `src/engine/effect-resolver.ts` | `planStackResolution`, `resolveEffects`, `applyStructuralZoneChange` |
| `src/engine/resolution-choices.ts` | Pause/continue instruction choices |
| `src/engine/proposed-events.ts` | Transform each produced instruction before committing its actual result |
| `src/engine/game-engine.ts` | Commit results, save continuations/triggers and finish checkpoint |
| `src/engine/effect-context.ts` | Runtime planning dependencies, including shuffle randomness |

At resolution start, all explicit targets are revalidated. If at least one target was chosen and all are now illegal, the entire object fails: no instructions execute. With surviving targets, applicable instructions and untargeted effects continue. Choosing zero targets for an optional clause does not itself make the object fail. Triggered intervening conditions are checked separately.

## Flow

```text
Top stack object → intervening condition/target decision
 → ordered effects (each sees earlier actual planned results)
 → optional choice/replacement pause and saved cursor
 → final spell destination or ability removal
 → actual report/events → checkpoint → priority
```

Targets' permission/type legality locks at resolution start. Later instructions still require the original identity to exist, so leaving/reentering cannot regain applicability. A permission change made by an earlier instruction does not rerun the complete targeting decision. The spell stays on the stack during its instructions. Failed/countered spells go to graveyard; supported permanent spells enter battlefield; abilities remove only their stack object.

## Extension boundary and remaining work

The structural permanent classifier currently covers Creature, Artifact, Enchantment and Land; family additions in 8.3 must extend that general classifier and entry state together. Spell copies need distinct stack/physical-card lifecycle rules in 8.4. Add effects through the registry, keeping the shared planner and its runtime context on initial and resumed paths.

## Acceptance evidence

`tests/engine/object-resolution.test.ts` proves all/partially illegal results, optional-zero targeting, stack presence, locked legality and returned-object exclusion. `tests/engine/pending-choices.test.ts` proves cursor resumption without repeating effects. `tests/engine/operation-outcomes.test.ts` proves dependency recovery and prepared shuffle outcomes through replacement pauses.

## Stop condition

Stop if a primitive independently determines whole-object failure, a spell moves before its instructions, or a resumed resolution repeats earlier effects/random planning.
