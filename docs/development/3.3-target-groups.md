# 3.3 — Target groups and legality

Status: implemented grouped announcement and resolution revalidation; broader targeting-system review remains explicitly deferred. Inspected at `c651cda`, 12 October 2026. [Development index](README.md).

## Purpose and current contracts

Keep announced targets distinct from nontargeted selections and from resolving “all matching” effects. A physical UUID alone must not allow a departed/reentered object to remain a target.

| Module | Owns |
|---|---|
| `src/shared/target-legality.ts` | `describeTargetGroups`, structural legality, exact identity lookup/keys and shared permissions |
| `src/engine/target-groups.ts` | `planTargetGroups`, complete group validation and locked references |
| `src/engine/modifier-registry.ts` | Shared target permission facade |
| `src/engine/effect-resolver.ts` | `revalidateTargets` and whole-object legality decision |
| `src/engine/choices.ts` | Filtered options for targeted/nontargeted requests |
| `src/types/effect.types.ts` | Target definitions, pointers and stack groups |

Group IDs derive from an authored shared clause or effect index. Every group is validated for membership, count, uniqueness, structure and permissions. The legacy flat format remains usable when its mapping is unambiguous; otherwise groups are required. Card targets are normalized to UUID, zone and revision. Stack targets use stack identity. Pointer decoration cannot disguise a duplicate identity.

## Flow

```text
Selected modes → target-group definitions → options/selections
 → validate every group → lock exact references on stack
 → resolution-start revalidation → whole-object decision → surviving targets
```

Structural queries use current effective types, subtypes, control, power/toughness and zone. Permissions include effective shroud, hexproof/protection and extension predicates. “All” expansion is nontargeted; resolution selections must not invent an announced target after costs were paid.

## Extension boundary and remaining work

Preserve announcement → validation → stack → resolution-start revalidation. [Whole-object resolution](3.4-object-resolution.md) defines when legality locks. Variable target groups and richer card definitions remain 8.4. Full targeting architecture review is a later owner decision; this document does not authorize a rewrite or claim every target rule is modeled.

## Acceptance evidence

`tests/engine/target-groups.test.ts` covers all groups, malformed selections, effective control/type/power/permission changes, returned objects, shared clauses and stack-type filters. `tests/engine/object-resolution.test.ts` covers all/partially illegal outcomes. Permission changes and socket revalidation are in `tests/server/live-routing.test.ts`.

## Stop condition

Stop if a new target consumer ignores revisions, skips nonfirst groups or turns nontargeted selection into targeting to reuse a UI path.
