# 7.2 — Replacement ordering, finite shields and continuations

Status: implemented supported operations, affected-player choices and serializable nested transactions. Inspected at `60e9349`, 12 October 2026. [Development index](README.md).

## Purpose and structure

When multiple rules apply, the affected player chooses, then applicability is recalculated. Finite resources and earlier previewed results must survive a pause without committing early.

| Module | Responsibility |
|---|---|
| `src/types/proposed-event.types.ts` | Definitions, applied-rule lineages, completed/remaining instructions, parent transactions and resolution tail |
| `src/engine/replacement-rules.ts` | `registerReplacementOperation`, applicability, source/lifetime checks and built-in operations |
| `src/engine/proposed-events.ts` | Self precedence, optional declines, finite use/prevention accounting and resume |
| `src/engine/game-reducer.ts` | Room sequence IDs and explicit registration/removal |
| `src/engine/game-engine.ts` | Owned choice validation and continuation completion |

Definitions contain serializable operation data. Engine handler code registers separately; unknown handlers fail explicitly. Built-ins cover scale, prevent, redirect, destination change, cancel and regeneration. Self-replacements precede ordinary candidates. Descendants inherit used rule IDs, so a rule cannot repeatedly replace its own changed result. Declining an optional rule is recorded for that lineage.

## Flow

```text
Event frame → self/ordinary applicable rules → affected-player selection
 → operation result + previewed resource consumption → reevaluate descendants
 → optional nested choice → restore parents → prepared atomic batch and saved response tail
```

Finite event uses consume only when an operation changes the event. Prevention shields reserve actual prevented amounts. Competing simultaneous sources can request a prevention distribution. Unpreventable damage encounters prevention without reducing its shield. Saved parent transactions keep result-created damage inside the outer atomic batch; `afterResolution` resumes the next instruction afterward.

## Extension boundary and remaining work

Extend `ReplacementOperationMap` and register a pure applicability/replace handler. Handlers return events/mutations, never checkpoints or callbacks in state. New exotic optional/loop families need explicit termination/choice semantics under 9.1; applied-rule lineage alone is not a general loop solver. Durable restart loading is 9.3 even though continuations currently round-trip as JSON.

## Acceptance evidence

`tests/engine/proposed-events.test.ts` covers chosen orders, redirection, split descendants, shield distribution and nested result choices. `tests/engine/replacement-registration.test.ts` covers identity/lifetime/unpreventable damage. `tests/engine/replacement-transactions.test.ts` and `tests/server/live-routing.test.ts` prove paused atomic work, no early completion and reconnect.

## Stop condition

Stop if a paused prefix spends a shield/cost early, one rule reapplies to its descendant, handlers mutate the room, or reconnect needs hidden closure state.
