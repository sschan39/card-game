# 9.4 — Browser scenarios and engine invariants

Status: real Socket.IO and component scenarios exist; automated two-browser suite and property-based invariant harness remain open. Inspected at `60e9349`, 12 October 2026. [Development index](README.md).

## Current evidence

`tests/server/live-routing.test.ts` starts actual server source, two real clients and the existing delta reducer. `tests/client/pending-choices.test.ts` and `tests/client/mana-options.test.ts` exercise real component callbacks. `vitest.config.mts` runs `.test.ts` files in Node. No browser-runner dependency/configuration is present in package metadata. `docs/playwright-smoke-testing.md` is a manual historical reference, not a maintained executable E2E suite.

## Proposed structure

| Unit | Responsibility |
|---|---|
| Browser match fixture | Two isolated sessions, real server/client, explicit cleanup and deterministic generic fixtures |
| Scenario drivers | User-visible actions/choices with observable convergence; event-based waits |
| Engine invariant generator | Legal/illegal instruction sequences constrained by the chosen profile |
| Assertions/artifacts | Conservation, exact revisions, nonnegative supported resources, stable checkpoints and replay equivalence; failing seed/transcript |

## Proposed flow

```text
Controlled baseline → two browsers perform visible actions → assert both views/choice ownership
 → reconnect/recovery case → record failing transcript/artifacts if needed → close all resources

Generated engine inputs → supported operation → invariant/checkpoint/replay assertions → reproducible failing seed
```

## Extension boundary and remaining work

Cover timing, allocation, targeted triggers, replacements, reconnect and game end as real interactions. Hidden-information scenarios depend on deferred 0.3 and cannot be declared passing under full debug snapshots. Use public DOM/interaction contracts; the old smoke reference's React-private-handler invocation and fixed waits are not a robust E2E design. A general server factory remains deferred 0.5 unless a demonstrated consumer justifies it.

## Acceptance required

Executable reproducible browser commands in CI/local runs, no fixed-wait correctness, deterministic failures, exact ownership/sequence assertions and no browser/socket/server/timer leaks. Invariant coverage must distinguish legal rules behavior from arbitrary malformed mutation injection; a generator mirroring the reducer is weak evidence.

## Stop condition

Stop if the browser suite bypasses user interactions through private framework hooks, “invariants” duplicate implementation logic, or tests hide genuine empty-library rules with blanket deck filling.
