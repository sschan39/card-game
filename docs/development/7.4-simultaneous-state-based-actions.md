# 7.4 — Extended simultaneous state-based settlement

Status: implemented supported checks, persistent legend/protector decisions and terminal convergence. Inspected at `60e9349`, 12 October 2026. [Development index](README.md).

## Purpose and structure

Gather all current conditions from one board, collect required decisions before any batch changes, then repeat settlement until stable.

| Module | Responsibility |
|---|---|
| `src/engine/state-based-planner.ts` | `planStateBasedActions`, `answerStateBasedChoice`, shared batch and exact-reference decisions |
| `src/types/state-based.types.ts` | Saved decisions/batch references and resume priority |
| `src/engine/state-based-actions.ts` | Existing check facade |
| `src/engine/game-engine.ts` | Repeated checkpoints, simultaneous cause/context and priority gating |
| `src/engine/proposed-events.ts` | Relevant removal/result replacements before commit |

Checks cover zero toughness, lethal/deathtouch destruction, opposing counters, departed-token cessation, Aura legality, Equipment/Fortification detachment, legend/world uniqueness, loyalty/defense, battle protector, life/poison/failed-draw losses. Siege defense waits for its relevant pending/stacked trigger. World tenure follows gaining/regaining the supertype. Departed tokens cannot return before cessation.

## Flow

```text
One effective board snapshot → conditions + APNAP decisions
 → persist decision or prepare complete batch → replacements → simultaneous commit
 → preceding-state witnesses → repeat checks → schedule triggers → restore priority
```

Legend/protector decisions retain exact references and survive reconstruction. Invalid/stale answers do not partially apply the batch. Overlapping removal reasons produce one actual removal. All simultaneous changes precede terminal freezing; simultaneous player losses produce a draw rather than an iteration-order winner.

## Extension boundary and remaining work

Settlement foundations do not create tokens/copies or implement attachment casting/equip, loyalty actions or battle defeat gameplay. Those remain Milestone 8. Richer profiles and multiplayer outcomes need explicit definitions. New SBAs must use a shared snapshot and decision protocol, preserving loss ordering and witness information.

## Acceptance evidence

`tests/engine/state-based-extended.test.ts` covers every listed condition/decision family. `tests/engine/m7-boundaries.test.ts` covers token return, Siege/World and simultaneous terminal changes. `tests/server/live-routing.test.ts` restores a legend choice and settles before priority. [Simultaneous witnesses](4.5-simultaneous-witnesses.md) explains the event context contract.

## Stop condition

Stop if one permanent is settled/checkpointed at a time, a decision pays part of the batch early, or a game-over reducer freezes before other simultaneous changes apply.
