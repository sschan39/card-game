# 5.2 — Live combat participants and blocked status

Status: implemented revision/controller/type reconciliation and current characteristics at damage planning. Inspected at `60e9349`, 12 October 2026. [Development index](README.md).

## Purpose and structure

Declaration snapshots identify original combat objects; their stored power is not the authoritative damage amount.

| Module | Responsibility |
|---|---|
| `src/engine/combat-state.ts` | `liveCombatCard` and `reconcileCombat` |
| `src/engine/handlers/declare-attackers-handler.ts` | Capture declaration snapshots and explicit unblocked state |
| `src/engine/handlers/declare-blockers-handler.ts` | Record block assignments/completion |
| `src/engine/game-reducer.ts` | Reconcile after effective state changes |
| `src/engine/combat-service.ts` | Read live sources/recipients and effective power for each damage pass |

Live participation requires battlefield presence, original UUID/revision, matching effective controller and effective Creature type. Invalid participants are permanently pruned; a physical card returning later cannot rejoin that declaration. A blocked attacker stays blocked after its last blocker leaves. Participant snapshots remain useful debug evidence; current damage queries read effective characteristics.

## Flow

```text
Declaration snapshot → state/characteristic change → prune invalid participants
 → preserve blocked flag → damage planning reads current surviving objects
 → end-combat response window → clear combat on leaving combat
```

## Extension boundary and remaining work

Additional attack destinations need their own exact reference/controller context in 5.7. Extra combats need 9.1's per-combat reset policy; current `attackedThisTurn` validation must be revisited there. Keep identity reconciliation in one shared place rather than fixing individual damage handlers.

## Stop condition

Stop if combat follows UUID alone, vanished blockers clear blocked status, or declaration-time power replaces live damage queries.
