# Ordered library implementation plan

> Execute inline with the executing-plans skill, one bounded slice. Design: [approved ordered-library contract](8.1-ordered-library-operations.md), approved 12 October 2026.

**Goal:** Keep the authoritative library as an ordered list while exposing safe top/bottom transfers and state-preserving in-place permutations.

**Architecture:** Reuse `MOVE_CARD`, the replacement transaction and committed operation outcomes. Share exact permutation validation between shuffle/reorder, preserving their different semantic outcomes. No new dependencies, settings, client components or named-card mechanics.

## Task 1 — Demonstrate the missing behavior

- [x] Create `tests/engine/library-ordering.test.ts` with exact deck fixtures and draw assertions for both placements; subset/full reorder identity assertions; invalid permutation/input tables; ordinary delta/event assertions; replacement cancellation/redirect/serialized pause coverage.
- [x] Extend `tests/server/live-routing.test.ts` with synthetic ordered effects through ordinary socket casting, both client views and reconnect.
- [x] Run the focused files with the bundled Node and `node_modules/vitest/vitest.mjs run`; confirm missing reorder/placement behavior fails before engine edits.

## Task 2 — Engine primitives and consumers

- [x] Create `src/types/library.types.ts` with `LibraryCardReference`, `LibraryPlacement` and `MoveZoneParameters` from the approved design. Extend `src/types/game-mutation.types.ts` with `REORDER_LIBRARY`, shared shuffle reference typing, and optional `MOVE_CARD.zoneRevision/libraryPlacement`.
- [x] In `src/engine/library-operations.ts`, share complete permutation validation; add `planLibraryReorder` and `applyLibraryReorder`. The planner reverses the selected top-to-bottom list once and prepends/appends it to untouched cards. The reducer preserves card/state references and distinguishes unchanged reorder from successful unchanged shuffle.
- [x] In `src/engine/game-reducer.ts`, route `REORDER_LIBRARY` through its operation outcome.
- [x] In `src/server/sync-service.ts`, map `REORDER_LIBRARY` to the existing exact deck update; retain current recipient filtering.
- [x] In `src/engine/zone-transitions.ts`, extract `validateCardMove` from existing preflight checks. Validate optional exact revisions and placement/index combinations; resolve top/bottom against the actual destination deck in `moveCard`.
- [x] In `src/engine/proposed-events.ts`, use shared validation before original transfer replacement discovery, retaining ordinary final validation for replacement results.
- [x] In `src/engine/effect-registry.ts`, validate typed movement parameters, capture exact source references and preserve legacy unplaced sequencing. For placed movement, group by owner and reverse each group for top insertion; keep input sequence for bottom insertion. Add `REORDER_LIBRARY` effect over one library's exact selected references. Reject ambiguous mixed same-zone/transfer requests before planning.
- [x] Run focused tests, inspect every failure and correct structural causes; no compensating reorder, setup mutation or ad hoc bypass.
