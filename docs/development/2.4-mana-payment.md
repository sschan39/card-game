# 2.4 — Mana costs and payment

Status: generic/colored/explicit-colorless payment and allocation choices implemented; broader cost symbols and alternate/additional costs remain open under 8.4. Inspected at `c651cda`, 12 October 2026. [Development index](README.md).

## Purpose and current contracts

Distinguish what a cost requires from which real pool resources pay it. `ManaCost` in `src/types/card.types.ts` can include generic; `ManaPayment` contains only the six pool colors. Generic is not a seventh stored resource.

| Module | Owns |
|---|---|
| `src/engine/mana-pool.ts` | `validManaAmounts`, `ManaPool.proposePayment` and affordability |
| `src/library/card-parser.ts` | `parseManaCost`: supported numeric/colored/colorless symbols; explicit rejection of unknown syntax |
| `src/engine/action-costs.ts` | Shared pure cost plan and selected nested mana activations |
| `src/engine/action-choices.ts` | `choosePayment` opens an allocation request; completed answers return to action validation |
| `src/types/choice.types.ts` | Serializable payment options/limits/total and action continuation |
| `src/client/components/ChoicePanel.tsx` | Existing allocation controls |
| `src/engine/game-reducer.ts` | `SPEND_MANA` applies a concrete allocation |

Automatic payment reserves specific colored/colorless requirements, then spends generic from remaining mana in `MANA_COLORS` order: colorless, white, blue, black, red, green. A submitted allocation must use known colors, nonnegative safe integers, the exact total, available resources and every specific requirement. The planner returns a copy and never spends authoritative resources.

## Flow

```text
Announced cost/selections → preview selected mana activations
 → optional allocation choice → revalidate entire action
 → concrete SPEND_MANA plus other costs → one action commit → checkpoint
```

Milestone 3 extended the original setup/mana slice: mana abilities can now share discard/sacrifice costs, and missing selections can use existing choices. An invalid final payment leaves all previewed taps, sacrifices and mana output unpaid/uncommitted. A card being cast stays reserved against nested discard costs.

## Extension boundary and remaining work

Normalize variable/alternate/additional costs into one selected payable cost before this planner. Cost selection and mana allocation are distinct decisions. Unsupported symbols must reject explicitly; do not interpret unknown symbols as free. No new payment setting is needed for current behavior. The fuller cost-selection schema remains 8.4.

## Acceptance evidence

`tests/engine/setup-mana.test.ts` covers specific/generic payment and forged allocations. `tests/engine/action-costs.test.ts` covers nested activation rollback and source reservation. `tests/engine/pending-choices.test.ts` checks revalidation of submitted payment without consuming a bad answer. `tests/client/pending-choices.test.ts` covers allocation submission. `tests/server/live-routing.test.ts` covers concrete payment, both clients and reconnect.

## Stop condition

Stop if a new cost symbol is ignored, if options spend resources, or if an invalid final action leaves a mana activation committed.
