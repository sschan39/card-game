# 3.6 — Countering and retained source information

Status: implemented selected stack countering and source-independent abilities for supported objects. Inspected at `c651cda`, 12 October 2026. [Development index](README.md).

## Purpose and current structure

An ability remains a stack object after its source departs. Countering selects an object and removes its effects without undoing paid costs or moving an ability's source.

| Module | Owns |
|---|---|
| `src/engine/effect-registry.ts` | Generic `COUNTER` produces `COUNTER_STACK` |
| `src/engine/game-reducer.ts` | Selected spell transfer to graveyard or ability-only stack removal |
| `src/engine/source-information.ts` | `captureSourceInformation`, `retainDepartingSource`, `resolveSourceInformation` |
| `src/engine/zone-transitions.ts` | Capture departure before reset; refresh waiting source snapshots |
| `src/engine/effect-resolver.ts` | Dynamic source parameters and permission revalidation |
| `src/types/effect.types.ts` | Separate spell/activated/triggered stack objects and optional `sourceInfo` |

Counter pointers carry stack UUIDs and may filter spell/ability types. A spell's physical card moves from stack; an ability's source stays wherever it is. Other stack objects remain intact. Actual counter/removal events are derived after application.

## Source lookup flow

```text
Original source UUID + zone + revision
 → exact live source: resolve current characteristics
 → otherwise current stack object's retained snapshot
 → otherwise saved object/departure event information
 → dynamic instruction values and legality queries
```

Capture stores effective characteristics and layer-1 copiable characteristics. A later physical-card return has a new revision and cannot replace the old source. Zone movement refreshes waiting stack/trigger/delayed source information before reset. Simultaneous departures use the shared preceding state. Activation with source sacrifice retains predeparture information through the cost/stack lifecycle.

## Extension boundary and remaining work

Use retained information only where the rule/effect asks for the original source; it does not make that object a live recipient again. Static effects and independent resolved effects have separate lifetimes in Milestone 6. Spell copies, uncounterable restrictions and replacement of counter destinations need their own general contracts under 8.4/7; selected counter support does not claim those families complete.

## Acceptance evidence

`tests/engine/source-information.test.ts` covers live changes, departure/reentry, sacrifice, simultaneous witnesses and generic dynamic parameters. `tests/engine/target-groups.test.ts` covers stack-type distinctions. `tests/server/live-routing.test.ts` drives ordinary counterspell priority and retained departure snapshots through deltas/reconnect. Existing cost tests prove payment remains after countering.

## Stop condition

Stop if source lookup follows UUID alone, countering deletes the source of an ability, or departure information is reconstructed from a reset/reentered card.
