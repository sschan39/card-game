# 5.5 — Attack/block legality and consequence hooks

Status: base declaration rules, existing Flying adapter and extension hooks implemented; new combat keyword consumers remain deferred. Inspected at `60e9349`, 12 October 2026. [Development index](README.md).

## Purpose and structure

Validate a complete declaration using effective characteristics and focused pure extensions.

| Module | Responsibility |
|---|---|
| `src/engine/handlers/declare-attackers-handler.ts` | Active player/step, controlled untapped creatures, duplicates, sickness and attacked flag |
| `src/engine/handlers/declare-blockers-handler.ts` | Defender/step, live attackers, controlled untapped blockers and duplicate assignments |
| `src/engine/combat-rules.ts` | Pairwise permission, whole-declaration constraints and consequence transforms |
| `src/engine/card-characteristic-service.ts` | Effective type/controller/keyword queries |
| `src/engine/player-commands.ts` | Turn-based declaration followed by active-player response priority |

`CombatRuleRegistry.register` returns an unregister function. Hooks may allow attacks despite sickness, supply pairwise block opinions, constrain groups and transform tapping/other declaration consequences. Pairwise exceptions do not erase whole-declaration restrictions. Blocking itself does not tap a blocker. Empty declarations are valid. Declaration completion prevents repeated submission.

## Flow

```text
Declaration-owner packet → base live validation → pair/group rule validation
 → pure consequence plan → commit declaration → checkpoint → response priority
```

## Extension boundary and remaining work

Haste attack permission, Reach, Vigilance, Menace, Defender and richer requirements remain deferred consumers. Effective Haste already participates in activation orientation costs; that does not implement the combat hook. Attack destinations/multiplayer require separate context extensions. Hook code must be registered in the engine, not serialized in room state.

## Acceptance evidence

`tests/engine/combat-state.test.ts` proves effective Flying, synthetic sickness permission, pair exceptions, whole-declaration constraints and consequences. `tests/engine/effective-characteristic-consumers.test.ts` proves gained/lost effective combat values. Manual/socket declaration regressions remain in existing suites.

## Stop condition

Stop if new rules need card-name branches, bypass complete-declaration checks, or turn declarations into stack objects.
