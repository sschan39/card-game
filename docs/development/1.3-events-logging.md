# 1.3 — Committed events, JSONL and deltas

Status: Implemented actual-state batches and explicit operation outcomes for semantic success.

Inspected source baseline: `ad6a96e`, 12 October 2026. [Development index](README.md). Source inspection documents current structure; test paths below identify verification responsibilities, not a new passing run.

## Purpose

Make rule notifications and logs reflect committed outcomes and expose extension points for new events.

## Current structure

- `src/engine/applied-events.ts` — AppliedMutation, sameStateValue and deriveAppliedEvents.
- `src/types/game-event.types.ts` — extensible GameEventPayloads and batch identities.
- `src/engine/game-engine.ts` — commitPreparedMutations and drainEventBatches.
- `src/shared/game-logger.ts` — structured sinks/batch recording.
- `src/server/sync-service.ts` — explicit mutation-to-delta mappings.

Event derivation uses actual before/after steps and explicit committed outcomes. Generic MUTATION_APPLIED records preserve mutation data alongside semantic events. Batches carry command/cause/parent identities; reducer replay and client delta replay are separate concerns. The approved 8.1 outcome boundary now preserves semantic success even when state stays equal. Legacy setters retain unchanged/no-event behavior.

## Flow

```text
Prepared mutation → pure operation outcome → committed step → owned or derived semantics → rule discovery/logs → explicit state delta
```

## Extension boundary

Extend typed payloads and choose one semantic event owner without adding one logger per event. Every state mutation also needs sync coverage. The working contract is in [8.1 operation outcomes](8.1-committed-operation-outcomes.md).

## Remaining work and modification notes

Record actual exported interfaces and replay limitations as they change. JSONL recording alone does not provide restart recovery or deterministic commands; those belong to 9.3.

## Acceptance evidence

- tests/engine/applied-events.test.ts, tests/shared/game-logger.test.ts and tests/server/sync-service.test.ts cover actual changes, generic records and delta replay.
- New equal-state semantic outcomes require rejection/redundant/success distinctions and exactly-once event evidence.

## Stop condition

Stop if events are emitted while planning, a logger silently discards new payloads, or dummy state changes are used to force semantic publication.
