# 0.5 — General integration harness

Status: Focused actual-server tests exist; general injectable server factory remains deferred.

Inspected source baseline: `ad6a96e`, 12 October 2026. [Development index](README.md). Source inspection documents current structure; test paths below identify verification responsibilities, not a new passing run.

## Purpose

Provide reusable real-server test construction only when new scenarios need its broader dependencies.

## Current structure

- `tests/server/live-routing.test.ts` — actual source server, two clients and test-local fixtures.
- `src/server.ts` — current server wiring/lifecycle.
- `src/server/state-store.ts` — StateStore interface and in-memory implementation.

The focused tests import the real server rather than copying its routing branches. The proposed full server factory with injected store/clock/randomness and explicit startup/shutdown has not been authorized by the earlier harness decision.

## Flow

```text
Existing focused test → actual source server → two Socket.IO clients → real routing → cleanup
```

## Extension boundary

Prefer narrow dependency inputs on the real server when a feature needs them. A general factory must own transport lifecycle and expose explicit shutdown, not create a second server implementation.

## Remaining work and modification notes

Revisit factory design when replay/time/store consumers justify it. Do not substitute test-only production methods or expand the harness before its consumers are specified.

## Acceptance evidence

- tests/server/live-routing.test.ts is the primary existing integration seam.
- Future harness gates require ephemeral ports, close-on-failure cleanup, no leaked listeners/timers and fixtures for mechanics absent from the prototype deck.

## Stop condition

Stop if integration verification requires copied socket handlers, invisible fixture bypasses or production-only test hooks that do not serve the engine.
